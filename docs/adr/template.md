# NNN — Short decision title

- **Status:** Proposed — awaiting Tony's approval | Accepted | Superseded by NNN | Rejected
- **Date:** YYYY-MM-DD
- **Ticket:** (e.g. O-01)
- **Deciders:** Tony (Solutions Architect) approves before merge
- **Related:** links to other ADRs, plan sections, API docs

## Context

What is true today, grounded in the code (file paths, tables, routes). What forces
the decision: product needs, constraints, risks, data-handling considerations (what is logged, stored, or sent to third parties).

## Decision

What we will do. Be specific enough that an implementation agent can build it
without re-deciding: schemas, state transitions, error contracts, migration
filenames and order, rollout phases.

## Consequences

What becomes easier or harder. Follow-up work, operational impact, migration and
rollback behavior, test obligations.

## Alternatives considered

Each option, and why it was not chosen.

## Open questions

Decisions that still need an owner. Mark each with who decides and what it blocks.
